## 一、语音库收口：85 句台词，37 组，只剩一处来源

改造前台词散在 **8 个地方**（动作库、部位定义、余额模块、渲染进程的拖拽数组、
主进程的提示字符串、独立的对话库…）。那个状态必然导致三个问题：改一句台词
得先找它在哪个模块；同一场景可能写在两处；没人答得出"她一共会说多少句话"。

现在**唯一来源**是 `src/shared-core/voice-library.js`，每个组都必须声明
`trigger`（触发条件）：

| 触发条件 | 什么时候说 | 附加条件 | 组 / 条 |
|---|---|---|---|
| `idle` | 闲置主动对话（每 1 分钟） | 固定 / 好感度 / 心情 | 9 / 27 |
| `click` | 点击身体部位 | 部位 × 好感度三档 | 12 / 24 |
| `action` | 播放某个动作 | 动作 id | 6 / 6 |
| `trust` | 心情差时被关心 | — | 1 / 3 |
| `drag` | 被拎起来 | — | 1 / 3 |
| `balance` | 余额播报（拼进句子） | 余额档位 | 4 / 4 |
| `system` | 系统提示 | 场景 id | 3 / 3 |
| `free` | 「随机说一句」 | — | 1 / 15 |

**合计 37 组 / 85 条**，逐条可在 `VOICE-LIBRARY.md` 里核对（该文档由库生成，
测试会断言"文档 === 库"，改了台词忘了重新生成会红）。

### 点击部位的三个档位

| 档位 | 语气 | 示例（摸头） |
|---|---|---|
| 0~1 心 | 惊讶 + 防备 | 「呀！别、别突然摸头啦。」 |
| 2~3 心 | 嘴硬但放松 | 「摸头也不是不行……轻一点。」 |
| 4~5 心 | 宠溺 + 羞涩 | 「……再摸一会儿也可以。」 |

三档整表由主进程随 `clickParts` 下发，渲染进程按爱心数本地选 —— 点击必须零延迟。

### 加新语音的规矩

先定**触发条件** → 有同条件的组就加进那个组 → 没有就新建组 →
跑 `node scripts/dev/gen-voice-doc.mjs` → 跑 `npm test`。
字数上限（24 字）、跨组去重、文档同步三条都有断言守着。

## 二、好感度：5 条增长途径 + 数值浮出

| 途径 | 增量 | 约束 |
|---|---|---|
| 闲置主动对话 | **+1** | 每次触发 |
| 点击桌宠互动 | **随机 2~8** | **每 5 分钟一次** |
| 随机动作触发 | **+2** | 只算随机抽中，菜单手动点不算 |
| 连续运行 10 分钟 | **+5** | 独立定时器，与宿主忙闲/睡眠无关 |
| 心情 < 50 时点击 | **+10** | 与"点击 2~8"**共用** 5 分钟冷却 |

> 第 5 条共用冷却是刻意的：两条都挂在同一个动作上，若 +10 不受冷却，
> 低心情时连点即可每分钟刷上百点。

**可视化反馈**：好感/心情变化时角色上方浮出 `好感 +N` / `心情 +N`。
放在独立图层且 `pointer-events: none`，**不拦鼠标命中**；增量由主进程给出
（晋心时阶段值归 0，diff 会得出"好感 −95"这种负数）；周期漂移不弹。

**低心情点击的特殊分支**：心情 < 50 时点击 → 心情立即 **+50**、说一句**信赖语音**，
且不播部位动画、不说部位台词。

## 五、轻量化：素材换成 WebP，包体 145 MB → 约 31 MB

桌宠"本体"之所以大，全部来自素材：**131 帧、143 MB、平均 1.1 MB/帧**
（864×1157 RGBA）。源码与依赖加起来不到 1 MB。

在 4 张代表性帧上比过几种方案：

| 方案 | 体积 | 可见 RGB PSNR | alpha |
|---|---|---|---|
| PNG 无损优化 | 96~100% | 无损 | 无损 |
| WebP 无损 | 69~71% | 无损 | 无损 |
| **WebP q92（采用）** | **19~23%** | ~34.5 dB | **无损** |
| 缩到 720 宽 + PNG | 72~76% | ~24 dB（边缘软化） | 46 dB |

选 q92 的关键：**alpha 完全无损**（轮廓/阴影边缘不会有调色板那种硬边），
而 RGB 的损失在实际显示尺寸下**看不出来** —— 素材 864 宽，桌宠只用 180~400 px 显示，
浏览器本来就要缩 2~4 倍；1:1 对比才看得出极轻微差异。

实测：素材 **143.10 MB → 29.27 MB（20.5%）**，安装包 **145 MB → 约 31 MB**。

> 这也说明"桌宠本体有点大"不是代码胖，而是画质本身高。
> 想再小只能降分辨率，那会真的影响观感 —— 这次没做。

## 六、好感度会存档了（用户数据与安装目录分离）

| 项 | 位置 / 说明 |
|---|---|
| 存档文件 | `%APPDATA%\DSH Pet\affection.json` |
| 内容 | 爱心数、阶段好感值、点击冷却锚点、累计获得量 |
| 写入 | 原子写（`.tmp` + rename）；变更后延迟 800ms 合并写，**退出时强制刷盘** |
| 读取 | 启动时在开窗之前载入；坏文件按"没有存档"处理且**不删除** |

**这也是"升级不丢数据"的结构性保证**：两个安装器清理的都是插件安装目录，
而存档在 `%APPDATA%\DSH Pet\`，两者完全不在同一棵树里 ——
所以不需要安装器"记得跳过某个文件"，它压根碰不到。

> 心情**仍然不存**：用户要求每次启动重置为满值，这是刻意与好感不同的设计。

## 七、升级：装新版本会自动清掉旧版本文件

不用再手动卸载旧版本 —— 两个安装器都会先清理再安装。

| 安装器 | 清理什么 | 保留什么 |
|---|---|---|
| `install.cmd` / `install-pet.ps1` | profile 里 `node_modules\dsh-pet-ds` 与 `node_modules\.pnpm\dsh-pet-ds@*` | `<DSH_HOME>\dsh-pet-ds\`（你的配置、日志） |
| `setup.exe` | 目标安装目录（`<你选的目录>\dsh-pet-ds\`）里的旧文件 | 同上 |

**为什么必须清**：`setup.exe` 的载荷是"叠加解压"的，pnpm 又把包装在
`按来源路径取名`的目录里。不清就会留下新版本里已经不存在的旧文件，
表现为「装的是新版、跑的还是旧代码」——最难查的一类问题。

### 两个安全约束

1. **不会误删联接目标**：开发版的 `node_modules\dsh-pet-ds` 是指向工作区的
   Junction，递归删除会清空用户的工作区。所以先按"链接"删（`rmdir`），
   只有确认是普通目录才递归删。
2. **不会清空你选的其它目录**：`setup.exe` 只在"目录里有 `package.json`
   且 `name` 是本插件"时才清理；其它非空目录**直接拒绝**并让你换一个空目录。

日志里会看到 `[upgrade]`（正在清理旧版本）或 `[refuse]`（拒绝安装）标签。

## 八、本版修复的两个真 bug

1. **好感面板要等下一次推送才刷新**（你反馈的「一开始没变化，点击之后才反馈」）。
   根因：展开面板时只重绘了心情、**漏了好感**，而推送处理里写着
   `if (statsVisible) renderAffection()` —— 面板隐藏期间的变化不会被画。
2. **装完 DSH 显示「异常 / 包不可用」**：pnpm 那步失败时旧脚本仍然登记配置，
   留下"登记了但解析不到"的坏状态。现在**装不上就回滚**并明确报错。

## 安装

### 方式一：一键安装（推荐，双击即可）

解压 `桌宠插件-一键安装.zip`，双击 **`install.cmd`**。五步：

```
[1/5] 插件包体   [2/5] DSH 配置目录   [3/5] Node 与 pnpm
[4/5] 安装       [5/5] Electron 运行时
```

会自动装好插件与 **Electron 38.2.0**（约 120 MB，需联网；已存在则跳过）。
装完**重启 DSH**，桌宠自动出现。

### 方式二：交给 DSH 自己装

把 `dsh-pet-ds-0.2.0.tgz` 交给 DSH 的插件页（**添加插件 → 填 tgz 绝对路径**），
或命令行：

```powershell
dsh plugin --profile desktop install
```

DSH 会用自己那套解析规则装依赖，最稳。

### 方式三：`setup.exe`

带 UAC 的图形化安装器，载荷里**内嵌了依赖树**，不需要联网装依赖。
