# v0.1.3 — 一份能照着做完的手动安装文档

这一版只做一件事：**把"手动安装"写成可以真正照着做完的文档**，
并把之前散落、重复、甚至写错的安装说明整理干净。

## 新增

**`INSTALL-MANUAL.md` —— 手动安装指引。**

原先 `INSTALL.md` 里有一节"完全手动"，但它只写到"改两个字段 + 跑 pnpm install"
就结束了，没有验证手段；而且随着上面几版不断加内容，那一节和前面的
"三种安装方式"**各重复了一遍**（`## A.` 与 `## B.` 各出现两次），
还留了一句**与事实相反**的话（"动画素材不在仓库里"）。

新文档按"每一步都能自己确认对不对"来写：

| 内容 | 说明 |
|---|---|
| 两处改动 + 一条命令 | 明确"手动安装到底改了什么"，以及 `bundles` 为什么是唯一依据 |
| 五步流程 | 每步后面附**验证命令**，前一步不过就别往下走 |
| 装完四件事 | 把"有工具没桌宠"和"没工具"分开 —— 排障时最省时间的一刀 |
| **五个坑** | 每个都给出**确切的报错特征** |
| **加载链路图** | 六段链路，任何一段断了都表现为"DSH 里没有插件"；附症状→断在哪一段的对照表 |
| 六项自检清单 | 一段可直接粘贴的 PowerShell |

其中"五个坑"是这几版真实踩出来的，不是设想：

- 路径必须绝对、且用正斜杠（相对路径跨盘会解析失败）；
- **BOM**：`Set-Content -Encoding utf8` 写出的 JSON 带 BOM，而带 BOM 的 JSON 非法，
  DSH 读不了那个 profile —— 而 BOM **不可见**；
- **只跑 `pnpm add` 装不完整**：它会成功、依赖也装好、入口也解析得到，
  但**不写 `dsh.profile.bundles`**，而那是 DSH 认插件的唯一依据；
- `failed to import` 的**两种成因**（依赖没声明 / 插件目录不在解析链上），
  以及为什么"用 `.tgz` 装"天然没这个问题；
- 改完文件不重启就以为没生效（宿主侧要重启 DSH，桌宠侧只重启桌宠）。

## 修复

**`INSTALL.md` 的结构与一处事实错误。**

- 删掉重复的 `## A.` / `## B.`（502 行 → 233 行），改成单一层级：
  `0`（官方命令）/ `A`（安装器）/ `A′`（只有 `.tgz`）/ `B`（指向手动文档）；
- **改掉"动画素材不在仓库里"这句错话** —— 素材（10 个动作、116 个文件）
  **确实提交在版本库里**，这正是"源码归档必须自足"那条教训的要求。
  原句会让人以为要自己准备素材；
- **卸载一节改用官方命令**：补上实测过的 `plugin_manager remove_bundle`，
  它比安装器的 `--uninstall` 多做四件事（清 `node_modules` 与 lock、
  关桥接端口、**收掉桌宠进程**、`applied` 免重启）；
- 补回被删掉的 `stopOnUnload` 说明。

## 变更

**文档里的版本号改为占位符。**

`RELEASE.md` / `INSTALL.md` / `INSTALL-MANUAL.md` 里原本硬写着 `0.1.2`
（产物名、`tar -xzf` 示例、tag 命令、Release 表单……）。逐版回来改必然漏，
而漏掉的地方会让人照着一个不存在的文件名操作。现在统一成 `<版本>`。

> 只留一处具体的版本号：`RELEASE.md` 里"界面显示 0.1.0、包却是 0.1.2"
> —— 那是**举例说明版本漂移**，与当前版本无关。

## 安装 / 升级

三种方式任选，详见 [INSTALL.md](../INSTALL.md)：

```bash
# 官方命令（推荐，热生效）
plugin_manager( action="install_bundle", target="<这个 .tgz 的绝对路径>" )

# 安装器（有目录时）
node install.mjs

# 完全手动
见 INSTALL-MANUAL.md
```
