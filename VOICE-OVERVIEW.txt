2. 加台词：在那一组末尾加一行，行号接着往下写（如 3. 新的一句）；
3. 删台词：把那一行整行删掉（我可以按缺号识别）；

四、本次审查结论（"所有能说话的地方是否都在库里"）

查过全部会显示台词的入口，结论如下：

| 能说话的地方 | 台词来源 | 在库里？ |
| --- | --- | --- |
| 右键「动作」选中某个动作 / 闲置随机动作 | action-* 组 | ✅ 是 |
| 点击身体部位（按好感三档） | click-* 组 | ✅ 是 |
| 低心情时点击 | trust 组 | ✅ 是（见下方说明） |
| 拖动角色 | drag 组 | ✅ 是 |
| 余额跨档播报 | balance-tier-* 组 | ✅ 是 |
| 调整尺寸失败 / 刷新状态 / 点空白处 | system-* 组 | ✅ 是 |
| 闲置主动对话 / 右键「对话」/ 随机说一句 | idle-* 与 free-* 组 | ✅ 是 |
| 深度思考三段的动作 | 无台词（用户要求不发声） | ✅ 有意静音 |
| 宿主下发的一次性消息 / say 指令 | 由宿主提供文本 | ➖ 外部输入，不归库管 |

这次审查发现并修掉的一处例外：渲染进程里有一句硬编码兜底
「（占位·信赖）……哼，我才没有高兴。」—— 主进程没给信赖台词时它会顶上，
既不在库里、也改不到。现在改成"没给就不说话"，并加了测试
scripts/dev/test-voice-sources.mjs：只要有人再往 showBubble('中文…') 里写死台词，测试立刻红。

> 你问的「吃白饭、玩mc、坐下、睡觉」四个动作：它们一直在库里，
> 就是第一节「播放动作」里的 action-eat / action-play-mc / action-sit / action-sleep，
> 只是每组只有 1 句占位台词，所以看起来像"没配"。想加词直接在那组里加行号即可。
